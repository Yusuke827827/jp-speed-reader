# 事業運営ガイド（エージェントの使い方）

アプリを収益化するための、経理・税務・法務・マーケティングの担当を、Claude Code のサブエージェントとして `.claude/agents/` に置いています。AI が書類の下書きと整理をし、**最終判断は、必要に応じて実際の税理士・公認会計士・弁護士に確認します。**

## エージェント一覧

| エージェント | 役割 | 使いどころ |
|---|---|---|
| `accounting`（経理） | 売上・経費の記録、仕分け、月次の突合 | 毎月の締め、「これは経費？」 |
| `tax-advisor`（税理士役） | 確定申告・青色申告・消費税・副業の住民税の準備 | 開業、申告前、税理士への相談前 |
| `cpa`（会計士役） | 収支分析、損益分岐、資金繰り、価格の採算、法人化の試算 | 価格を決める、投資先を選ぶ |
| `legal-ops`（法務） | 規約・ポリシーの更新、ストア審査、OSSライセンス、リリース前チェック | 機能を足す前、申請の前 |
| `lawyer`（弁護士役） | 著作権・商標・苦情対応のリスク評価、弁護士への相談判定とブリーフ | 申立てが来た、名称を決める |
| `marketing`（マーケ） | ストア掲載文、発信計画、同時リリースの戦略 | 申請前、リリース週 |

呼び方の例：

- 「`accounting` で、今月のストアの売上と経費を整理して」
- 「`legal-ops` で、広告を入れる前の規約とポリシーの点検をして」
- 「`marketing` で、3本同時リリースの告知計画を作って」

担当の間で判断が分かれるものは、次の順で回します：`accounting` → `tax-advisor`（税務）／`cpa`（分析）、`legal-ops` → `lawyer`（リスク）→ 実際の弁護士。

## 守るルール

1. **このリポジトリは公開です。** 帳簿、領収書、契約書、口座番号、マイナンバー、取引先の個人情報は、`private/` 以下にだけ置きます（`.gitignore` 済みで、コミットされません）。
2. 税制・ストア規約・手数料は変わります。エージェントは、公式情報を調べて、出典と確認日を書く決まりです。
3. 実際の専門家に相談する場面の目安：税務の申告方法に迷う、紛争・警告書が来た、金額の大きい契約をする、個人情報の漏えいが疑われる。

## 事業の前提（ここを埋めると、エージェントの精度が上がります）

公開されるファイルなので、住所・電話番号・口座・実績の金額は書かないでください。

| 項目 | 内容 |
|---|---|
| 運営者の区分 | 【未入力：会社員の副業／専業／法人】 |
| 開業届・青色申告の届出 | 【未入力：済／未】 |
| アプリ | Flowa（`jp-speed-reader`）、hikidashi、kintore-app |
| 配布先 | Web（GitHub Pages）。App Store・Google Play は、1年目の予算の範囲で順に出す |
| 収益の方針 | 収益化したい（方法は未定：買い切り／課金／広告） |
| 開発環境 | Mac なし。iOS のビルドは GitHub Actions の macOS 環境を使う |
| 1年目の予算（想定） | 約6〜10万円（ストア登録 約1.9万円、ドメイン 約0.5万円、会計ソフト、規約レビュー、税理士の初回相談など） |
