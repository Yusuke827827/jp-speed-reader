# 速読リーダー（jp-speed-reader）

日本語の小説PDFやテキスト（青空文庫形式を含む）を取り込み、本文を短い単位に分けて画面中央に1つずつ表示する高速読書Webアプリです。ルビは漢字の上に表示し、登録した人物名は色分けして説明を添えます。通常のPDFビューアとしても使えます。PDF・本文・読書位置はすべて端末のブラウザ内（IndexedDB）に保存し、外部のサーバーには送りません。

## セットアップと起動

Node.js 20.19 以上または 22.12 以上が必要です（Vite 8 の要件。Node 24.21 / npm 11.19 で動作を確認）。

```bash
npm install
npm run dev        # 開発サーバー（http://localhost:5173、同じLANのスマホからも開ける）
npm test           # 単体テスト・統合テスト（Vitest）
npm run build      # 本番ビルド（dist/ に出力。PWA の Service Worker も生成）
npm run preview    # 本番ビルドの確認（http://localhost:4173）
```

`npm run dev` と `npm run build` の前に、`scripts/copy-assets.mjs` が PDF.js の CMap・標準フォントと、Tesseract.js の本体を `public/` に複製します。

動作確認用のサンプルPDF（このアプリ用に書いた短い文章）は `public/samples/` にあり、取り込み画面の「サンプルで試す」から読み込めます。作り直すときは `python -I scripts/make_samples.py` を実行します（PyMuPDF と游明朝フォントが必要）。英語の論文風サンプル（2段組み・両端揃え・行末のハイフン分割・柱・ページ番号・段の下の脚注・参考文献・付録）は `node scripts/make_en_sample.mjs` で作ります（pdf-lib の標準フォントを使うので追加の準備は不要）。

### iPhoneで使う

1. 本番ビルドを HTTPS で配信します（GitHub Pages、Cloudflare Pages、Netlify など。静的ファイルだけで動きます）。サブパスに置く場合は `BASE=/リポジトリ名/ npm run build` でビルドします。
2. iPhoneのSafariで開き、「共有 → ホーム画面に追加」を選びます。
3. ホーム画面のアイコンから起動すると、全画面で動き、オフラインでも読み込み済みの本を読めます。

同じLAN内のPCで `npm run dev` を動かし、iPhoneから `http://PCのIPアドレス:5173` を開いて試すこともできます。この場合は HTTPS ではないので、PWA のインストールとオフライン起動は使えません。

## 仕組み

### 本文の抽出（`src/lib/layout.ts`）

PDF.js が返す文字の断片を座標で行（縦書きなら列）にまとめ、段落を組み立てます。

- 縦書き／横書きは、フォントの縦書き指定と断片の形、1文字ずつ配置されたPDFでは隣の文字の位置で判定します。
- 本文の中央値より明らかに小さい文字（約0.62倍未満）はルビとして除きます。
- ページの上下端の行のうち、多くのページに共通する行（柱）、本文より小さい行、数字だけの行（ノンブル）を除きます。
- 行頭の字下げ・開き括弧・前の行が短く句点で終わることを手がかりに段落を区切り、段落の途中でページが変わる場合は前のページの段落につなぎます。
- 康熙部首（⽇→日）・CJK互換漢字・半角カナを正規化し、青空文庫形式のルビ《》と注記［＃］を外します。
- 1ページの文字が8字未満、または私用領域の文字や置換文字が1割を超える場合は、OCRの対象にします。

### テキストの取り込み（`src/lib/textImport.ts`）

文字コードは UTF-8 を試し、読めなければ Shift_JIS とみなします。青空文庫形式なら、1行目を題名、2行目を著者とし、記号の説明と末尾の「底本：」以降を除きます。［＃「…」は大見出し］などの注記から目次を作ります。本文は段落の切れ目で約1200字ごとの仮のページに分けて保存します（PDF表示はありません）。

### 挿絵（`src/lib/illust.ts`）

取り込み時に、文字の取れないページを小さく描いて塗りの割合を測り、0.4%未満なら白紙とします。本文の多いPDFでは、残りを挿絵のページとみなし、OCRの対象から外します。文字のあるページでも、描画命令から画像の位置を求め、ページの12%以上を占める画像があれば挿絵入りのページとして、その範囲を記録します（本文ページの6割以上に大きな画像がある場合は背景とみなして除きます）。ほぼ全ページが画像のスキャンPDFでは、OCRの結果が15字未満か信頼度45%未満のページを挿絵とみなします。

読書中は、挿絵を段落の切れ目に差し込みます（挿絵のページをはさんで続く段落は切りません）。挿絵の位置に来たら「止まる（タップで続きから）」「決まった秒数だけ表示」「飛ばす」から選べます。挿絵を表示する時間は、読書速度の計算に含めません。判定が違うページは、PDF表示の画面の「挿絵にする」ボタンで切り替えられます。

### ルビ

本文は内部で「｜漢字《かんじ》」の記法で持ち、読むときに本文とルビの位置に分けます（`parseRuby`）。青空文庫形式のテキストはそのまま使えます。PDFでは、本文より小さいかな・カタカナの並びを、縦書きなら列の右、横書きなら行の上にある文字と座標で重ね合わせ、親文字に結び付けます。座標からの推定なので、組版によっては結び付けを誤ったり、取りこぼしたりします。

### 人物（`src/lib/people.ts`）

本ごとに人物（名前・別名・色・説明）を登録します。登録した名前は途中で区切らず、色分けし、名前を含む単位の表示時間を少し延ばします（文字数換算で1.5字分。区間の平均速度は変わりません）。説明は「章の最初の3回」「本の最初の3回」「毎回」から選べます。章は目次の見出しで区切ります。候補として、ルビ付きの語、敬称の直前の語、3回以上出るカタカナ語を本文から拾います。人名でない語も混ざるので、登録は利用者が選びます。

### 分割（`src/lib/segment.ts`）

段落を文に分け（括弧内の句点では切らない）、Google の BudouX で文節相当の単位にしたうえで、モードに合わせてつなぎ直します。

| モード | 内容 |
|---|---|
| 1文字 | 1文字ずつ。句読点・閉じ括弧・小書き文字は前に、開き括弧は後ろにつける |
| 2〜4文字 | 文節を4文字以内に収める |
| 文節 | BudouX の単位（10文字を超える場合は字種の境目で切る） |
| フレーズ（初期値） | 文節をつないで目標文字数（4〜14、初期値7）にそろえる |
| 文 | 1文ずつ。28文字を超える文は読点で分ける |

数字・英単語・三点リーダー・ダッシュ・ルビの親文字・登録した人物名の途中では切りません。

英語など欧文が主の文（空白以外の文字の半分以上がラテン文字）は、BudouX を使わず単語単位で分けます。「1文字」「2〜4文字」は1語ずつ、「文節」は1文字の語（a、I）を次の語とつなぎ、「フレーズ」は日本語の1文字を欧文の2文字とみなして数語ずつ、「文」は80字を超える文をカンマなどで分けます。文はピリオドでも区切りますが、略語（Dr.、Fig.、e.g. など）・頭文字（J. R.）・小数・次が小文字で始まる場合は区切りません。欧文の単位は語数を持ち、速度は「語/分（WPM）」で合わせます（初期値250、60〜1200）。欧文が主の本では、読書画面の速度表示と＋−ボタンが WPM になります。日本語と欧文が混ざった本では、日本語の部分は字/分、欧文の部分は WPM の設定で表示します。中央表示では単語間の空白を詰められない空白で描き、全文パネルでは文と文の間の空白も描きます。

「最小の字数」（初期値3字）より短い単位は、同じ文の隣の単位とつなぎます。初期値は参考動画に合わせて「文節」「3字以上」「紙色の背景」です。会話の開き括弧の前と、読点・閉じ括弧の後では単位を区切ります。分割モードを変えても、読書位置は本文の文字位置で保持されます。

形態素解析器（kuromoji など）は辞書ファイルが大きく、iPhoneでの初回読み込みが重くなるため使っていません。BudouX の日本語モデルは約24KBです。

### 速度（`src/lib/timing.ts`）

速度の単位は「文字/分」（空白を除く）です。各単位に「文字数＋句読点の間」の重みを与え、段落の切れ目でまとめた約240字ごとの区間で「区間の文字数÷区間の表示時間」が設定値と一致するよう、表示時間を配分します。間を入れても、区間ごとの平均速度は設定どおりです。間の大きさは文字数換算で、読点1.5、句点3、段落末5です（倍率は設定で変えられます）。

1単位の表示時間には40msの下限があります。下限のせいで設定速度を出せない極端な設定（1文字モードで約1500字/分以上など）では、速度の表示に「（上限）」と出ます。

再生直後の4単位は、表示時間を1.7倍・1.4倍・1.2倍・1.08倍にして目を慣らします（設定でオフにできます）。一時停止時に出る「実測」は、この減速と句読点の間を含めた、実際の表示文字数÷経過時間です。

日本語の本では、画面に参考値として「単位/分」と「WPM」も出します。この WPM は BudouX の文節を1語とみなした換算で、英語の WPM とは厳密には比べられません。英語など欧文の文は、別に設定する語/分（WPM）で表示時間を決めます（`unitsOf`：1語を「字/分 ÷ 語/分」字ぶんとして扱う）。

### OCR（`src/lib/ocr.ts`）

Tesseract.js（jpn / jpn_vert / eng）で1ページずつ認識し、そのつど保存します。英語の文書は「英語」を選ぶか、自動判定で英語主体と分かったページを英語の学習データでも読み直し、信頼度の高い方を使います。英語の認識結果は、行の間に空白を入れ、行末のハイフンで分かれた単語をつないで本文にします。

- 縦横の「自動判定」では、最初のページを縦書き・横書きの両方で認識し、平均信頼度の高い方を残りのページに使います。
- ページは長辺2200pxで描画します。iPhoneのキャンバス上限（約1677万画素）を超えないよう、1200万画素で頭打ちにしています。
- 途中で中止・終了しても、処理済みのページは残ります。次回は未処理のページだけを処理します。
- Tesseract.js の本体（worker と wasm）はアプリに同梱しています。日本語の学習データ（jpn・jpn_vert、各数MB）は、初回だけ jsDelivr の CDN から取得し、以後はブラウザ内にキャッシュされます。CDN に送るのはファイルの要求だけで、本文や画像は送りません。

### 保存（`src/lib/db.ts`）

IndexedDB に、本の情報、元のPDF、ページごとの本文、読書位置、読書記録、しおり、設定を保存します。読書位置は「段落番号＋段落内の文字位置」で持ち、ページ番号・読了率・累計読書時間・最終読書日時も記録します。再生中は5秒ごと、一時停止時、画面を離れるとき（`visibilitychange` / `pagehide`）に保存します。OCRや手修正で本文が変わった場合は、保存したページ番号から位置を引き直します。

### 画面の言語（`src/lib/i18n.ts`）

画面は日本語と英語に対応しています。端末の言語が日本語なら日本語、それ以外なら英語で表示し、読書設定の「画面の言語」で切り替えられます。文言は日本語の文をそのままキーにして `t('本棚')` のように書き、英語の訳は `src/i18n/en/` に画面ごとに置きます。値の埋め込みは `t('{done} / {total} ページ', { done, total })` のように書きます。`src/lib/i18n.test.ts` が、訳の抜けと、`t()` を通さない日本語の文字列が画面のソースに残っていないかを確かめます。アプリ名は `APP_NAME` の1か所で決めています（英語名は仮）。

## iPhone の Safari での制約

| 項目 | 内容と対応 |
|---|---|
| データの自動削除 | ホーム画面に追加していないサイトのデータは、7日間使わないと Safari が削除することがあります。ホーム画面に追加して使ってください。取り込み時に `navigator.storage.persist()` で保護を依頼していますが、許可されるかはブラウザ次第です。 |
| 保存容量 | 上限は端末の空き容量に応じて変わります。容量不足のときはエラー文で、本の削除を案内します。 |
| バックグラウンド | 画面ロックや別アプリへの切り替えで、JavaScript は止まります。高速読書は自動で一時停止して位置を保存します。OCR は止まりますが、処理済みのページは保存されているので「続きから再開」できます。再生中・OCR中は、対応ブラウザ（iOS 16.4以降）で画面のスリープを止めます（Screen Wake Lock）。 |
| メモリ | OCR は1ページずつ処理し、描画に使ったキャンバスはすぐ解放します。数百ページのPDFでも一度に全ページを展開しません。ページ一覧のサムネイルは、画面に入ったページだけを描画します。 |
| ファイル選択 | 「ファイル」アプリ・iCloud Drive から選べます。iCloud 上だけにあるファイルは、先にダウンロードが必要な場合があります。 |

### 未実装・制限

- 横書きの左右2段組み（論文など）は、中央の文字の無い帯で段を分け、左の段、右の段の順に読みます。段をまたぐ題名などは段の前後に置きます。縦書きの段組み（1ページに上下2段など）と3段以上の段組みは判定していません。段ごとに順番が崩れる可能性があります。
- 論文の節の見出し（番号付きの短い行と、References・Appendix などの決まった見出し）と、字の大きさが前の行と変わる行（題名・著者）は、それだけで段落にします。
- 脚注は、横書きのページ（段組みなら各段）の下部で本文より小さい字の行が続く部分を除きます（本文の字の大きさは、文字数で重みを付けた最頻値）。字の大きさが本文と同じ脚注は除けません。
- 参考文献は、「References」「Bibliography」「参考文献」「引用文献」などの見出しから、付録（Appendix・付録）の見出しの手前までを、高速読書で飛ばします（設定で切り替え。初期値は飛ばす）。見出しの無い参考文献は判定できません。
- 縦中横（縦書き中の横向きの数字）は、PDF内の文字の並び順に依存します。
- OCRでは、ルビや傍点が本文に混ざることがあります。自作サンプル（縦書き2ページ、200dpi）での文字正解率は約96%でしたが、実際の小説スキャンでの精度は確かめていません。
- 割注・図版のキャプション・脚注の除去は行っていません。
- 挿絵の判定は画像の大きさと文字の量による推定です。文字を画像として埋め込んだPDFでは、本文ページを挿絵と誤ることがあります。テキスト（.txt）の挿絵注記（［＃挿絵…］）は画像が無いため表示しません。
- データのバックアップ（書き出し・読み込み）と、端末間の同期はありません。
- ピンチによる拡大はブラウザ標準の動作に任せています（ボタン・キー・ダブルクリックで拡大縮小できます）。
- 実機のiPhone（Safari）では確認していません。iPhone相当の画面幅（375×812）での表示・操作は、PC上のブラウザで確認しました。

## 構成

```
src/
  lib/
    normalize.ts   文字の正規化・文字化けの判定
    layout.ts      断片 → 行 → 段落、柱とノンブルの除去
    pdfItems.ts    PDF.js の出力 → 断片
    pdf.ts         PDF.js の読み込み・描画・目次
    importer.ts    取り込みの流れ
    ocr.ts         Tesseract.js による OCR
    book.ts        ページ → 段落列、本文位置とページの対応
    segment.ts     分割
    timing.ts      表示時間
    db.ts          IndexedDB
    settings.ts    設定
  ui/              各画面
scripts/
  copy-assets.mjs  PDF.js・Tesseract.js の付属ファイルを public/ に複製
  make_samples.py  サンプルPDFの生成
```
